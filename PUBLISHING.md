# Publishing

How the site is put together and how to add to it.

## What lives where

| Path | What it is | Editable by hand? |
|---|---|---|
| `index.html` | Home page | Yes |
| `ar/` | Arabic blog (RTL, hand-written) | Yes |
| `speaking/index.html` | Speaking page: topics, past talks, speaker bio | Yes |
| `thoughts/index.html` | A Muslim's thoughts (personal page) | Yes |
| `<slug>/index.html` at root | Generated legacy redirect stubs, see below | No |
| `_blogsrc/` | **Source** for the English blog | Yes — this is where you write |
| `blog/` | **Generated.** Do not edit by hand | No — `npm run build` overwrites it |
| `blog/media/` | Optimised post images (not generated) | Add files here |
| `tools/` | Migration + helper scripts | Yes |

The English blog is generated by [Eleventy](https://www.11ty.dev/) from `_blogsrc/`
into `blog/`, and the generated HTML is committed. GitHub Pages keeps serving the
branch exactly as it always has, so there is no build step between you and the
live site and nothing new that can fail on deploy.

## Add a post

```bash
./tools/new-post.sh "The machine that keeps Saudi mapped"
```

That creates `_blogsrc/posts/the-machine-that-keeps-saudi-mapped.md`:

```markdown
---
title: "The machine that keeps Saudi mapped"
date: "2026-08-20"
slug: "the-machine-that-keeps-saudi-mapped"
description: "One sentence. Shows on the index and in link previews."
archived: false
featured: true          # optional: pins it to "Start here" on the index
image: "https://ahmedkamal.me/blog/media/2026/stage.jpg"   # optional OG image
---

Write in Markdown.

## A section heading
```

Then:

```bash
npm install         # first time only
npm run dev         # write with live reload: http://localhost:8080/blog/
npm run build       # regenerate blog/
git add -A && git commit -m "Post: the machine that keeps Saudi mapped" && git push
```

Two ways to preview, good at different things:

- `npm run dev` — live reload as you type, but it serves **only** `/blog/`, so the
  home page, `/ar/` and `/thoughts/` links 404. Fine while writing.
- `npm run build && python3 -m http.server 8080` — serves the whole repo, so every
  link behaves exactly as it will in production. Use this to review before pushing.

Live within a minute of the push.

Notes:

- Three or more `##` headings switch on the sticky table of contents automatically.
- Reading time is computed, never written by hand.
- Images: put them in `blog/media/<year>/`, reference as `/blog/media/<year>/file.webp`.
  Convert first: `cwebp -q 82 photo.jpg -o blog/media/2026/photo.webp`.
- To unpublish something, move it to `_blogsrc/drafts/` and rebuild.
- The build never deletes, so if you rename or remove a post, delete its old
  folder under `blog/` by hand (otherwise the stale page stays reachable).

## Writing published elsewhere

`_blogsrc/_data/elsewhere.json` drives the "Published elsewhere" list on the index.
Add an entry and rebuild — no template changes:

```json
{
  "title": "Scaling Machine Learning at Careem",
  "url": "https://medium.com/careem-tech/...",
  "venue": "Tech @ Careem",
  "date": "2019-03-14",
  "note": "One line. Optional."
}
```

Add `"archived": true` to an entry and it moves to the "Also on Medium" list at the
bottom of `/blog/archive/` instead of appearing on the index. Removing that one word
promotes it to the front page.

Use this rather than mirroring the text. A copy on this domain would compete with
the original in search and lose, and pieces published under a company publication
raise an ownership question that a link does not.

The bar for the index: is it stronger than the posts already on the blog, and can it
not live here? Yoda passes both. A 500-word tooling post from 2017 does not.

## Configuration

`_blogsrc/_data/site.json` holds the two switches:

```json
"ga4_id": "G-7SGXTR10EE",   // live
"disqus_shortname": ""      // e.g. ahmedkamal -> turns on comments
```

Fill either one in and run `npm run build`. Empty means the snippet is not emitted
at all, so there are no broken scripts and nothing loading for no reason.

**Analytics:** live on `G-7SGXTR10EE`, across the blog, the home page, all eight
`/ar/` pages and `/thoughts/`. The dead `UA-124188722-1` property is gone from every
file. Every page carries a localhost guard, so `npm run dev` and
`python3 -m http.server` sessions are not recorded as real traffic — the console
logs `[analytics] local preview: GA4 disabled` instead.

Beyond GA4's enhanced measurement (page views, outbound clicks, file downloads,
90% scroll), posts emit a `read_depth` event at 25/50/75/100% with seconds elapsed,
`comments_open` when a reader opens Disqus, and `video_play` on embedded video.
The one page with no tag is `/blog/public-speaking/`, which only exists to redirect.

**Comments:** Disqus loads only when a reader clicks "Show comments". That keeps
~1MB of third-party JavaScript and its trackers off every page view. Comments are
enabled on current posts and off on archived ones.

## The archive

29 posts from 2012–2021 are online at their original slugs, served with
`noindex, follow`, carrying a dated banner, listed only at `/blog/archive/`, and
excluded from the index and the RSS feed. To promote one into the current stream,
add its slug to `PROMOTED` in `tools/migrate_ghost.py`, then
`npm run migrate && npm run build`, and add it to `sitemap.xml`.

26 unfinished Ghost drafts sit in `_blogsrc/drafts/`. They never build. To publish
one, move it to `_blogsrc/posts/` and give it a real `date`.

## Legacy URLs

The blog has lived at three addresses, so there are two generations of inbound
links to preserve.

**`ahmedkamal.me/<slug>/`** — the original apex-hosted era. Ahmed's own LinkedIn
profile still links `ahmedkamal.me/using-spark-for-data-exploration/`.
`tools/gen-legacy-redirects.py` writes a `noindex` stub at each of those paths
pointing to `/blog/<slug>/` with a `rel=canonical`. Re-run it after promoting or
adding posts:

```bash
python3 tools/gen-legacy-redirects.py
```

It refuses to touch `blog/`, `ar/`, `thoughts/`, `speaking/`, or any path holding a
real page. `/public-speaking/` maps to `/speaking/` rather than into the blog.

**`blog.ahmedkamal.me/<slug>/`** — the Ghost era. Still to set up. In Cloudflare,
**Rules → Redirect Rules**, create:

| Field | Value |
|---|---|
| When | Hostname equals `blog.ahmedkamal.me` |
| Then | Dynamic redirect, 301 |
| Expression | `concat("https://ahmedkamal.me/blog", http.request.uri.path)` |

Slugs were preserved 1:1, so every old `blog.ahmedkamal.me/<slug>/` link lands on
the right post. The 11 retired URLs will 404; `/blog/public-speaking/` and
`/public-speaking/` both redirect to `/speaking/`.

If you would rather have real 301s than meta-refresh stubs for the apex paths, a
Cloudflare rule can replace them and the generated directories can be deleted.

## Re-running the Ghost migration

Only needed if the triage in `tools/migrate_ghost.py` changes (the `PROMOTED`,
`FEATURED`, `RETIRE` and `RETITLE` lists at the top of the file):

```bash
npm run migrate && npm run build
```

It rewrites `_blogsrc/posts/`, `_blogsrc/drafts/` and `blog/media/` from the Ghost
backup, and is safe to re-run.
